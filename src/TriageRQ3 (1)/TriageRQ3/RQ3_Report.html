1. Tổng quan bài toán

Trong phòng cấp cứu (ER), bệnh nhân được phân loại theo mức độ ưu tiên (triage). Có hai cách tổ chức hàng đợi:

🔹 Single-Level Priority Queue (PQ đơn cấp)

Tất cả 500 bệnh nhân vào một hàng đợi duy nhất, sắp xếp theo priority (1 = khẩn cấp nhất, 10 = ít khẩn cấp nhất). Luôn rút ra bệnh nhân có priority thấp nhất (khẩn cấp nhất).

🔹 Multi-Level Priority Queue (PQ đa cấp 3 tier)

Bệnh nhân được chia vào 3 hàng đợi riêng biệt theo mức độ:

Tier Tên Priority range Ý nghĩa
1 Urgent 1 – 3 Cấp cứu ngay (đau tim, chấn thương nặng...)
2 Semi-Urgent 4 – 6 Cần xử lý sớm (gãy tay, sốt cao...)
3 Non-Urgent 7 – 10 Không khẩn cấp (cảm cúm, đau nhẹ...)

Quy tắc: Rút hết Tier 1 trước khi rút Tier 2, rút hết Tier 2 trước khi rút Tier 3.

🔹 Priority Drift là gì?

⚡ Priority Drift (Tình trạng thay đổi)

Trong thực tế, tình trạng bệnh nhân có thể xấu đi khi đang chờ. Ví dụ: bệnh nhân vào với đau bụng nhẹ (p=5, Semi-Urgent), chờ 30 phút → đau dữ dội, nghi viêm ruột thừa (p=2, Urgent).

Multi-Level PQ không tự di chuyển bệnh nhân sang tier mới → bệnh nhân nặng bị kẹt ở tier cũ → MISORDERING (sai thứ tự).

3.1 Patient.java — Đối tượng bệnh nhân

Patient.java — Lưu thông tin bệnh nhân: id, tên, priority (1-10), level/tier (1-3) 
public class Patient {
    private final int    id;
    private final String name;
    private final int    priority;   // 1-10, actual priority (may be drifted)
    private final int    level;      // 1/2/3 - tier for PQ routing

    // Constructor bình thường: level tự phân loại từ priority
    public Patient(int id, String name, int priority) {
        this.level = classifyLevel(priority);  // auto-classify
    }

    // Drift constructor: priority thay đổi nhưng GIỮ tier cũ
    public Patient(int id, String name, int priority, int originalLevel) {
        this.level = originalLevel;  // KHÔNG re-classify!
    }

    // Phân loại: p 1-3 → Urgent, p 4-6 → Semi-Urgent, p 7-10 → Non-Urgent
    public static int classifyLevel(int p) {
        if (p <= 3) return 1;   // Urgent
        if (p <= 6) return 2;   // Semi-Urgent
        return 3;               // Non-Urgent
    }
}
💡 Điểm quan trọng

Hai constructor phục vụ hai mục đích khác nhau:

  • Constructor bình thường: bệnh nhân mới vào → level auto = classifyLevel(priority)
  • Drift constructor: priority đã thay đổi nhưng giữ originalLevel → mô phỏng bệnh nhân bị kẹt ở tier cũ

3.2 SingleLevelPQ.java — PQ đơn cấp

SingleLevelPQ.java — Một Min-Heap duy nhất, luôn extract bệnh nhân khẩn cấp nhất 
public class SingleLevelPQ {
    private final PriorityQueue<Patient> queue;

    public SingleLevelPQ() {
        // Sắp xếp theo priority tăng dần (1 = khẩn cấp nhất → ra trước)
        this.queue = new PriorityQueue<>((a, b) ->
            Integer.compare(a.getPriority(), b.getPriority()));
    }

    public void insert(Patient p)   { queue.offer(p); }     // O(log n)
    public Patient extract()       { return queue.poll(); }  // O(log n)
}
✅ Hoạt động

Tất cả 500 bệnh nhân vào 1 heap → extract() luôn trả về patient có priority nhỏ nhất (khẩn cấp nhất) → không bao giờ sai thứ tự.

3.3 MultiLevelPQ.java — PQ đa cấp 3 tier

MultiLevelPQ.java — 3 Min-Heap riêng biệt cho 3 mức độ khẩn cấp 
public class MultiLevelPQ {
    private final PriorityQueue<Patient> urgent;       // Tier 1: p 1-3
    private final PriorityQueue<Patient> semiUrgent;   // Tier 2: p 4-6
    private final PriorityQueue<Patient> nonUrgent;    // Tier 3: p 7-10

    // INSERT: phân loại vào tier dựa trên level
    public void insert(Patient p) {
        switch (p.getLevel()) {          // ← dùng level (tier), KHÔNG dùng priority!
            case 1: urgent.offer(p);     break;
            case 2: semiUrgent.offer(p); break;
            default: nonUrgent.offer(p); break;
        }
    }

    // EXTRACT: rút hết Tier 1 trước, rồi Tier 2, rồi Tier 3
    public Patient extract() {
        if (!urgent.isEmpty())     return urgent.poll();
        if (!semiUrgent.isEmpty()) return semiUrgent.poll();
        return nonUrgent.poll();
    }
}
⚠️ Vấn đề khi có Priority Drift

insert() dùng getLevel() để phân tier. Nếu bệnh nhân có drift constructor (level = tier cũ), họ sẽ vào sai tier. Ví dụ: priority=2 (Urgent) nhưng level=2 (Semi-Urgent tier) → vào hàng Semi-Urgent!

b) Áp dụng Priority Drift

public List<Patient> applyDrift(List<Patient> original,
                                 double driftRate, long seed) {
    for (Patient p : original) {
        if (driftRng.nextDouble() < driftRate) {
            int drift = driftRng.nextInt(3) + 1;  // giảm 1-3 điểm
            int newP  = Math.max(1, p.getPriority() - drift);
            // Dùng drift constructor: GIỮ NGUYÊN level/tier cũ!
            drifted.add(new Patient(p.getId(), p.getName(), newP, p.getLevel()));
        } else {
            drifted.add(p);  // không thay đổi
        }
    }
}
💡 Tại sao giữ tier cũ?

Mô phỏng thực tế: khi bệnh nhân đã được xếp vào hàng đợi Semi-Urgent, nếu tình trạng xấu đi, Multi-Level PQ không tự động chuyển họ sang hàng Urgent. Bệnh nhân kẹt ở tier cũ.

c) Đo Misordering — Thuật toán cốt lõi

private MisorderingResult measureMisordering(String pqName,
        List<Patient> allPatients, List<Patient> extractionOrder) {

    // Bước 1: Tạo ideal order (sorted theo priority tăng dần)
    List<Patient> idealOrder = new ArrayList<>(allPatients);
    idealOrder.sort((a, b) -> Integer.compare(a.getPriority(), b.getPriority()));

    // Bước 2: So sánh từng vị trí
    for (int i = 0; i < size; i++) {
        Patient actual = extractionOrder.get(i);  // PQ rút ra
        Patient ideal  = idealOrder.get(i);       // lẽ ra phải là

        // Nếu actual priority > ideal priority → SAI THỨ TỰ!
        if (actual.getPriority() > ideal.getPriority()) {
            misorderCount++;
        }
    }
}
📐 Công thức đo misordering rate

misordering rate = (misorderCount / totalPatients) × 100%

Ideal order = danh sách 500 bệnh nhân sorted theo actual priority (tăng dần).

Extraction order = thứ tự thực tế mà PQ rút ra bệnh nhân.

So sánh từng vị trí: nếu PQ rút ra bệnh nhân có priority cao hơn (ít khẩn cấp hơn) so với ideal → đó là 1 misordering.

6. Trả lời Research Question 3

RQ3

Làm thế nào để đo lường tỷ lệ "sai thứ tự triage" (misordering rate) khi so sánh Priority Queue đơn cấp và Priority Queue đa cấp (urgent / semi-urgent / non-urgent) trên cùng một tập 500 ca bệnh mô phỏng?

6.1 Phương pháp đo lường Misordering Rate

  1. Tạo tập dữ liệu: 500 bệnh nhân ngẫu nhiên (seed cố định để reproducible) với phân bố thực tế: 20% Urgent (p=1-3), 50% Semi-Urgent (p=4-6), 30% Non-Urgent (p=7-10)
  2. Mô phỏng priority drift: Một tỷ lệ bệnh nhân (0%, 15%, 30%) có tình trạng xấu đi (priority giảm 1-3 điểm) SAU KHI đã được phân loại vào tier
  3. Tạo ideal order: Sắp xếp tất cả 500 bệnh nhân theo actual priority tăng dần — đây là thứ tự lý tưởng
  4. Extract từ PQ: Rút lần lượt bệnh nhân ra khỏi PQ → tạo extraction order
  5. So sánh: Tại mỗi vị trí i, nếu actual[i].priority > ideal[i].priority → đó là 1 misordering
  6. Tính tỷ lệ: misordering rate = misorderCount / 500 × 100%

6.3 Phân tích kết quả

Single-Level PQ — Luôn chính xác (0%)

  • Sử dụng 1 Min-Heap duy nhất cho tất cả bệnh nhân
  • extract() luôn trả về bệnh nhân có globally minimum priority
  • Không phụ thuộc vào tier/level → priority drift không ảnh hưởng
  • Complexity: Insert O(log n), Extract O(log n)

Multi-Level PQ — Misordering khi có drift (6-8.4%)

  • Sử dụng 3 Min-Heap riêng biệt cho 3 tier
  • Luôn rút hết Tier 1 trước → Tier 2 → Tier 3
  • Khi bệnh nhân drift (tình trạng xấu đi), họ không được chuyển tier
  • Bệnh nhân thực sự urgent nhưng kẹt ở Semi-Urgent tier → bị phục vụ sau tất cả bệnh nhân Urgent tier
  • 21-23 bệnh nhân urgent bị phục vụ muộn — đây là rủi ro y tế nghiêm trọng

6.4 Kết luận

📌 Kết luận RQ3

Phương pháp đo: Misordering rate được đo bằng cách so sánh thứ tự extraction thực tế của PQ với ideal order (sorted theo actual priority), đếm số vị trí mà bệnh nhân ít khẩn cấp hơn được phục vụ trước bệnh nhân khẩn cấp hơn.

Kết quả:

  • Single-Level PQ có misordering rate = 0% ở mọi mức drift — luôn extract globally minimum priority, không bị ảnh hưởng bởi priority drift.
  • Multi-Level PQ (3-tier) có misordering rate = 6.0% (15% drift) đến 8.4% (30% drift) — misorderings xảy ra khi tình trạng bệnh nhân thay đổi sau khi đã được phân loại vào tier.

Trade-off: Single-Level PQ chính xác hơn về mặt thứ tự, nhưng Multi-Level PQ vẫn có giá trị thực tiễn vì:

  • Cho phép bác sĩ batch-process theo nhóm severity (xử lý tất cả urgent trước, rồi semi-urgent)
  • Giảm cognitive load cho nhân viên y tế
  • Misordering rate 6-8.4% là chấp nhận được nếu có cơ chế re-triage định kỳ

Khuyến nghị: Nếu sử dụng Multi-Level PQ, cần bổ sung cơ chế re-triage định kỳ (kiểm tra lại tình trạng bệnh nhân đang chờ) để giảm misordering rate.
